## Подготовка Node.js и pnpm

При наличии nvm:

```sh
source ~/.nvm/nvm.sh
nvm install
nvm use
```

Установка nvm описана в [официальном руководстве](https://github.com/nvm-sh/nvm#installing-and-updating).
`.nvmrc` задаёт точную версию; `nvm install` нужен только при её отсутствии.
Без nvm можно установить ту же версию из [архива Node.js](https://nodejs.org/dist/v24.21.0/).

Если pnpm уже доступен, проверьте `pnpm --version` в корне проекта: нужна версия из
`packageManager`. Современный pnpm умеет выбирать закреплённую версию проекта.
Для запуска через Corepack, если он доступен, глобальная установка не требуется:

```sh
corepack pnpm --version
corepack pnpm install --frozen-lockfile
corepack pnpm format:check
corepack pnpm lint
corepack pnpm typecheck
```

В этой форме `corepack pnpm` заменяет `pnpm` во всех командах. При отсутствии pnpm и
Corepack можно временно получить нужную версию через npm:

```sh
npm exec --yes --package=pnpm@11.22.0 -- pnpm --version
npm exec --yes --package=pnpm@11.22.0 -- pnpm install --frozen-lockfile
```

Способы установки и совместимость описаны в [документации pnpm](https://pnpm.io/installation).
Инструменты не устанавливают обработчики Git. Текущая среда не требует `.env` или
секретов; `.env.example` явно отражает это.

## Рабочие команды

После `source ~/.nvm/nvm.sh && nvm use` выполните:

```sh
pnpm install --frozen-lockfile
pnpm format
pnpm format:check
pnpm lint
pnpm typecheck
```

`format` изменяет поддерживаемые Prettier файлы, включая инструкции и план. Остальные
три команды проверяют файлы без исправлений. Сначала форматируйте, затем запускайте
проверки и просматривайте diff. Обычная установка с `--frozen-lockfile` не обновляет
описания зависимостей.

Настройки pnpm находятся в `pnpm-workspace.yaml`; `.npmrc` задаёт публичный реестр npm.
Хранилище зависимостей расположено в игнорируемом `.cache/pnpm/store` внутри копии.
Глобальное виртуальное хранилище отключено, поэтому локальная установка и CI используют
одинаковую структуру `node_modules`.
`verifyDepsBeforeRun: error` запрещает командам проверки автоматически устанавливать
зависимости: при устаревшем `node_modules` сначала явно выполните установку.
Несовместимые среды и зависимости отклоняются; `minimumReleaseAgeStrict: true`
не позволяет pnpm автоматически записывать исключения для недавно опубликованных версий.

`lint` проверяет собственные JS/TS-файлы, включая `eslint.config.mjs` и
`vitest.config.ts`; предупреждения считаются ошибкой. `typecheck` проверяет эти
конфигурации и будущие общие скрипты в `scripts/` по корневому `tsconfig.json`.
Формат и линт производного кода не исправляются вручную: пути `**/generated/**`
исключены из этих инструментов. Файл `pnpm-lock.yaml` ведёт pnpm.

Vitest настроен для `scripts/**/*.test.ts`; тестов общих инструментов сейчас нет.
Команды `test`, `build`, `verify`, проверки контрактов и языковые команды пока
не добавлены. Они появятся вместе с настоящими реализациями в шагах плана;
текущие проверки не подтверждают готовность языковых SDK.

## Нативные инструменты последующих шагов

Для текущих корневых проверок Python, Go и Rust не требуются. Ниже — согласованная
матрица дальнейшей реализации, а не подтверждённая поддержка готовых пакетов:

| Область               | Среды и инструменты                                   | Владелец настройки и команд                                  |
| --------------------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| JavaScript/TypeScript | Node.js 22/24, TypeScript, Vitest, `tsup`             | `typescript/`, STEP-04; пакет pnpm workspace                 |
| Python                | Python 3.12/3.14, `uv`, Hatchling, Ruff, mypy, pytest | `python/`, STEP-05; `pyproject.toml` и `uv.lock`             |
| Go                    | Go 1.26/1.27, `gofmt`, `go vet`, testing, Staticcheck | `go/`, STEP-06; `go.mod` и нативные проверки                 |
| Rust                  | Cargo, rustfmt, Clippy, встроенные тесты              | Версия и минимальный компилятор — STEP-03; `rust/` — STEP-07 |
| Pine Script           | Pine Editor TradingView                               | `pinescript/`, STEP-08; настоящая компиляция в редакторе     |

Для Python установите `uv` по [официальному руководству](https://docs.astral.sh/uv/getting-started/installation/).
После появления `python/.python-version` команда `uv python install` из `python/`
установит выбранный Python, а `uv sync --locked` подготовит зависимости пакета.
Версии `uv` и проверяющих средств закрепляет STEP-05.

Go нужной версии устанавливается по [официальному руководству](https://go.dev/doc/install).
Минимальная версия в будущем `go.mod` — 1.26; точные версии компилятора и Staticcheck
закрепляет STEP-06. Не создавайте Go-модуль в корне.

Rust устанавливается через [rustup](https://rust-lang.org/tools/install/).
После выбора компилятора STEP-03 используйте его точную версию с компонентами
`rustfmt` и `clippy`; будущий `rust/rust-toolchain.toml` будет выбирать её автоматически.
Не выбирайте незакреплённый `stable` вместо проверенного компилятора проекта.

Корневые языковые команды будут делегировать нативным инструментам соответствующего
каталога. Полный `pnpm verify` и CI собираются в STEP-09, после появления всех пакетов.

## Файлы и локальные артефакты

`.editorconfig` задаёт UTF-8 и LF, `.gitattributes` нормализует текстовые файлы в Git.
`.gitignore` исключает зависимости, окружения, кеши, сборки, отчёты, локальные секреты
и временные архивы выпуска. Контракты, общие примеры, инструкции, нужный производный
код, `.env.example` и файлы фиксации зависимостей сохраняются в Git.

При проверке воспроизводимости копируйте исходные файлы в новый временный каталог
без `node_modules`, кешей и локальных `.env`, затем выполняйте установку с
`--frozen-lockfile` и три проверяющие команды. Наличие незакоммиченных файлов в этой
копии подтверждает локальную приёмку, но не интеграцию в `main`.
